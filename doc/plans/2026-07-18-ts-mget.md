# TS.MGET Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `TS.MGET` support to `RediStick-TimeSeries`, following the FILTER-builder and `RsTsValue` result-object design captured in `CLAUDE.local.md` (Phase 2).

**Architecture:** Mirrors the existing `RediStick-Json` batch-operation pattern already used in this package (`RsRedisEndpoint` extension + small `Object` subclasses for options/filters). Four new small classes (`RsTsFilter`, `RsTsFilterBuilder`, `RsTsMGetOptions`, `RsTsValue`) plus two new `RsRedisEndpoint` methods (`tsMGetFilterBy:` / `tsMGetFilterBy:using:`) and three private parsing helpers.

**Tech Stack:** Pharo Smalltalk, Tonel file format, SUnit (`TestCase` for pure unit tests, `RsRedisTestCase` for integration tests against a live Redis/RedisTimeSeries instance).

## Global Constraints

- Follow the Tonel style guide and Options-pattern conventions from the `smalltalk-dev:smalltalk-developer` skill (consult it before editing `.st` files).
- Method categories on `RsRedisEndpoint` extension methods: public methods use `*RediStick-TimeSeries`, private helpers use `*RediStick-TimeSeries-private` (matches existing methods in `RsRedisEndpoint.extension.st`).
- Required arguments are ordinary keyword arguments; the many-optional-argument command (`TS.MGET`) uses the `using: optionsBlock` pattern, same as `RsRedisEndpoint >> jsonArrPop:path:using:`.
- Timestamps from `TS.MGET` samples come back as Integers already (RESP2 reply) — no `asRediStickUnixTimestampMillis` conversion needed on the way *out*.
- Numeric sample values are parsed with the existing private helper `RsRedisEndpoint >> tsParseValue:` (`NumberParser parse:onError:`, falls back to the raw string).
- Labels are represented as a `Dictionary` on the Smalltalk side (matches `RsTsOptions >> labels:` / `TS.INFO` label handling elsewhere in the package).
- Test keys must use the `test:ts:mget:...` prefix and rely on `RsRedisTestCase dbIndex` / `RsRediStick` connection setup already provided by the base test case — do not add new connection bootstrapping.
- After every `.st` change, reimport the affected package(s) via the smalltalk-interop MCP (`import_package`) before running tests, per this repo's workflow (see `CLAUDE.md`).
- No baseline/CI changes needed — `RediStick-TimeSeries` / `RediStick-TimeSeries-Tests` and the `TimeSeries...` Metacello groups already exist and `TimeSeriesTests` is already in `.smalltalk.ston`'s `load:` list.

## File Structure

- Create: `src/RediStick-TimeSeries/RsTsFilter.class.st` — a single `TS.MGET`/`TS.MRANGE`-style FILTER expression (`label=value`, `label!=value`, `label=(v1,v2,...)`, `label!=(v1,v2,...)`, `label!=` (has-label), `label=` (no-label)), with an `asString` conversion to the exact Redis token.
- Create: `src/RediStick-TimeSeries/RsTsFilterBuilder.class.st` — accumulates `RsTsFilter` instances; passed into the `tsMGetFilterBy:` block so callers can write `filter label: 'a' eq: value; label: 'b' in: {v1. v2}`.
- Create: `src/RediStick-TimeSeries/RsTsMGetOptions.class.st` — `LATEST` / `WITHLABELS` / `SELECTED_LABELS label...` option flags, converted to a Redis argument array via `asArray`.
- Create: `src/RediStick-TimeSeries/RsTsValue.class.st` — result value object: `key`, `timestamp`, `value`, `labels` (a `Dictionary`).
- Modify: `src/RediStick-TimeSeries/RsRedisEndpoint.extension.st` — add `tsMGetFilterBy:`, `tsMGetFilterBy:using:`, and private helpers `tsParseMGetResult:`, `tsValueFromMGetRow:`, `tsLabelsDictionaryFrom:`.
- Create: `src/RediStick-TimeSeries-Tests/RsTsFilterTest.class.st` — pure unit tests for `RsTsFilter class >> ...` constructors and `asString`.
- Create: `src/RediStick-TimeSeries-Tests/RsTsFilterBuilderTest.class.st` — pure unit tests for cascade-building a filter list.
- Create: `src/RediStick-TimeSeries-Tests/RsTsMGetOptionsTest.class.st` — pure unit tests for `asArray` under each flag combination.
- Create: `src/RediStick-TimeSeries-Tests/RsTsValueTest.class.st` — pure unit test for accessors.

	^ opts asArray

	| builder options args result |
	builder := RsTsFilterBuilder new.
	filterBlock value: builder.
	builder filters isEmpty ifTrue: [ Error signal: 'At least one filter expression is required' ].
	options := RsTsMGetOptions new.

    "private"
	rawResult ifNil: [ ^ #() ].

    "private"
	| key labelsPairs sample |
	key := row first.

		timestamp: sample first
		value: (self tsParseValue: sample second)
